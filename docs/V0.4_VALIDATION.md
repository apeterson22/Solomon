- Voice status is truthful; a challenge is bound to one action and signed device session, and never replaces visual approval for critical actions.

- Admin includes Voice & Mobile, Calendars, expanded model diagnostics, and the existing documentation/configuration surfaces.

## r8 edge-device extension

- Nine photo-seeded device records are visible through `/v1/edge-devices` and Admin → Edge Devices.
- Five idempotent, relationship-linked goals are created in proposed state.
- Discovery preview is read-only and does not pair, flash, transmit, locate, or actuate.
- State changes require an identified operator, explicit confirmation, and an evidence note.
- Free cloud advisors cannot control devices or receive precise location data.
- USB fingerprints are refreshed every five seconds and Bluetooth advertisements are sampled every minute.
- New fingerprints default to pending quarantine and retain operator approval or denial across rescans.
- RSSI proximity is explicitly represented as an estimate, never an exact 20-foot assertion.
- Approval authorizes local analysis only; pairing, writes, firmware, transmission, and actuation remain blocked.
- Eight device-operation classes have independent request, approve, deny, expiry, execute, and evidence states.
- Bluetooth addresses are server-derived and BlueZ runs without shell interpolation.
- Critical operation parameters are schema-bounded and execution fails closed without a signed fingerprint adapter.
- Concurrent execution is prevented by an atomic approved-to-executing claim.

## Installation-time gates

The upgrade additionally performs checks that require the target machines:

1. Captures the current app and a transactionally consistent SQLite backup.
2. Confirms controller/worker role.
3. Installs v0.4 and waits up to 90 seconds for health.
4. Confirms `NoNewPrivileges=yes` and the restricted broker socket.
5. Validates truthful knowledge/RAG/Obsidian/dashboard status on controller host.
6. Seeds the release standard into review—not approved—state.
7. Executes a bounded, network-disabled broker smoke job.
8. Restarts and repeats the health and hardening checks.

The upgrade automatically restores the prior application/configuration and the
pre-upgrade knowledge ledger if any installation gate fails.
