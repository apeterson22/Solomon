# SolomonPrime v0.3 — Goals, Distributed Jobs, and Experiment Ledger

## Purpose

v0.3 turns the existing discovery/scheduler/tool-aware fabric into a bounded execution fabric. The model may reason about work, but deterministic policy decides where it runs and a fixed executor allowlist decides what may execute.

## Goal Engine

Goals represent persistent outcomes rather than one-off tasks.

Create a goal:

```bash
KEY=$(sudo cat /etc/solomonprime/api.key)
curl -s -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' \
  -d '{
    "name":"Safe storage architecture",
    "outcome":"Inventory and propose an optimal deduplicated layout for all controller host drives without destructive changes",
    "why":"Recover capacity and make long-term memory/data placement predictable",
    "priority":"high",
    "status":"active",
    "success_metrics":[
      {"metric":"bytes inventoried","target":"all mounted/approved roots"},
      {"metric":"destructive actions","target":0}
    ],
    "approval_requirements":["file deletion","filesystem changes","mount changes"]
  }' http://127.0.0.1:8765/v1/goals | jq
```

List goals:

```bash
curl -s -H "Authorization: Bearer $KEY" http://127.0.0.1:8765/v1/goals | jq
```

## Experiment Ledger

Experiments preserve hypothesis, controlled variables, resource budget, manifest hash, selected node, job, metrics, result, and artifact hashes.

```bash
curl -s -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' \
  -d '{
    "goal_id":"GOAL-2026-001",
    "title":"worker-node Python worker smoke benchmark",
    "hypothesis":"worker-node can execute a bounded background scientific job reliably",
    "metrics":["runtime_seconds","artifact_bytes"],
    "resource_budget":{"max_runtime_seconds":60,"max_memory_gb":2,"max_cpu_cores":2}
  }' http://127.0.0.1:8765/v1/experiments | jq
```

## Bounded Job Executor

Initial executor kinds are deliberately narrow:

- `python`
- `blender`
- `openscad`

The API does not accept an arbitrary shell command. Jobs run as the dedicated `solomonjob` account in a systemd sandbox with:

- `NoNewPrivileges=yes`
- `ProtectSystem=strict`
- `ProtectHome=yes`
- private temporary and mount namespaces
- SolomonPrime secrets/state/log paths inaccessible
- CPU, memory, runtime, and per-file size limits
- network disabled by default
- fixed executable mapping by job kind

Only `read_only` and `reversible` jobs auto-execute in v0.3. Mutating/destructive requests generate approval records but are intentionally not executable through this bounded worker.

### Dispatch a Python experiment

After both controller host and worker-node have been upgraded to v0.3:

```bash
curl -s -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' \
  -d '{
    "goal_id":"GOAL-2026-001",
    "experiment_id":"EXP-2026-001",
    "kind":"python",
    "workload_kind":"simulation",
    "risk":"reversible",
    "priority":"background",
    "source":"from pathlib import Path\nPath(\"result.txt\").write_text(\"hello from bounded SolomonPrime job\\n\")\nprint(\"done\")\n",
    "resources":{
      "min_ram_gb":4,
      "min_gpu_vram_gb":3,
      "preferred_gpu_vendor":"nvidia",
      "requires_gpu":true,
      "max_runtime_seconds":60,
      "max_memory_gb":4,
      "max_cpu_cores":2,
      "max_disk_gb":1
    },
    "allow_network":false
  }' http://127.0.0.1:8765/v1/jobs/submit | jq
```

Poll:

```bash
curl -s -H "Authorization: Bearer $KEY" http://127.0.0.1:8765/v1/jobs/JOB-... | jq
```

The controller polls the signed worker endpoint, updates the controller job record, and updates the linked experiment ledger when the job completes.

## Preferred endpoint

Every heartbeat now persists a deterministic preferred endpoint from the node's ranked paths. This is informational and does not override the scheduler's live reachability check.

Expected priority:

1. direct Ethernet
2. wired LAN
3. Wi-Fi
4. Tailscale

## Storage persistence

On controller host, `upgrade-v0.3.0.sh` calls `scripts/migrate-state-to-apps.sh` before installing the new runtime. Physical data moves under:

```text
/apps/solomonprime-data/state
/apps/solomonprime-data/log
```

Existing logical paths remain:

```text
/var/lib/solomonprime
/var/log/solomonprime
```

through persistent bind mounts. This moves memory databases, node registry, approvals, cloud quota ledger, audit chain, goals, jobs, experiment ledger, training candidates, and experiment records off the small root filesystem.
