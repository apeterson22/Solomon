# SolomonPrime v0.4 Knowledge Workspace

## Delivered capabilities

- Additive `knowledge.db`; v0.3.2 memory, goals, jobs, approvals and experiments remain unchanged.
- Governed record lifecycle: `draft -> review -> approved`, with reject and retire paths.
- Default retrieval includes approved records only.
- Hybrid ranking combines SQLite FTS5, deterministic offline feature-hash vectors,
  domain scope, confidence and importance.
- Every result includes a structured citation with record ID, version, source URI,
  source hash and content hash.
- Exact-content deduplication and explicit canonical-key/negation conflict candidates.
- Contradictions require an identified operator resolution.
- Consolidation is preview-only; no automatic pruning or retirement is implemented.
- Obsidian-compatible manual exchange. Imports are always untrusted drafts; exports
  contain approved records only. Automatic bidirectional sync remains disabled.
- Responsive authenticated Admin workspace at `/admin`, linked from the
  preserved Open WebUI chat/history/workspace experience.
- TED panel with truthful quota guardrails, job effectiveness, runtime,
  artifact evidence, RAG evaluations, and explicit unmetered cost/energy state.
- Admin model inventory and gated cloud-advisor model choices; downloaded
  models are never activated or downloaded automatically.

## Truthful vector scope

The built-in vector backend is `feature_hash_v1`, a dependency-free sparse feature
hash over tokens and adjacent token pairs. It supplies a deterministic vector
signal and survives offline operation, but it is not described as a neural semantic
embedding model. A neural backend must outperform the approved evaluation set and
receive operator approval before promotion.

## Security invariants

1. Drafts never enter normal prompt retrieval.
2. Agent-created records cannot enter directly as approved.
3. Approval requires an identified actor and is written to the event ledger.
4. Conflicts are surfaced, never silently resolved.
5. Obsidian paths are resolved beneath the configured vault; traversal is rejected.
6. Imported Markdown is bounded to 2 MB and remains a draft.
7. No v0.4 operation deletes prior databases or files.

## Primary endpoints

| Endpoint | Purpose |
|---|---|
| `GET /v1/improvement/status` | Truthful readiness and governance state |
| `GET /admin` | Unified SolomonPrime and TED operator workspace |
| `GET /v1/improvement/dashboard` | Compatibility redirect to `/admin` |
| `POST /v1/knowledge` | Create a draft or review record |
| `GET /v1/knowledge/search?q=...` | Approved-only hybrid retrieval |
| `POST /v1/knowledge/{id}/state` | Reviewed lifecycle transition |
| `GET /v1/knowledge/contradictions/list` | Open conflict candidates |
| `POST /v1/knowledge/contradictions/{id}/resolve` | Human resolution |
| `GET /v1/knowledge/consolidation/preview` | Non-mutating retirement candidates |
| `POST /v1/knowledge/obsidian/import` | Manual Markdown-to-draft import |
| `POST /v1/knowledge/obsidian/export` | Manual approved-record export |

## Deferred gates

- Neural semantic embeddings and learned reranking.
- Automatic bidirectional Obsidian synchronization.
- Automatic contradiction resolution.
- Destructive or automatic consolidation.
- Agent promotion of standards, SOPs or rules without human review.
