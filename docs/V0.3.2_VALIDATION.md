## Host-enforced upgrade checks

The controller and node upgrade scripts additionally require, on each target:

- pre-upgrade health and a rollback checkpoint;
- `NoNewPrivileges=yes` on the network-facing SolomonPrime service;
- broker socket mode `0660`, owner `root`, group `solomonprime`;
- authenticated Goal, Experiment, Job, and Improvement Status APIs;
- typed Job request schemas in OpenAPI;
- a real Python job submitted from a transient `NoNewPrivileges` client,
  completed through the protected broker and systemd sandbox;
- network disabled for the smoke job;
- expected output artifact present;
- health version `0.3.2` after final restart.

Only after those checks pass does the upgrader remove the obsolete sudoers
files. Any failure before completion triggers restoration of application code,
configuration, units, helpers, and previous socket state from the timestamped
rollback checkpoint.

## Scope boundary

This build environment cannot reproduce controller host/worker-node's installed systemd,
users, GPUs, mounts, and network. The real host smoke test is therefore a
mandatory part of each upgrade, not an optional post-install check.
